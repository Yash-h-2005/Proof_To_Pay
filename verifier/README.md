# Proof-to-Pay Independent Verifier

## Purpose
The independent verifier is a standalone module (Phase 7) that receives proof evidence generated by the robot (or simulator), independently validates the evidence against specific rules, and determines if the task can be marked as `VERIFIED`.

## Architecture
```
Robot Simulator -> Backend -> [In-Memory Storage] -> Verifier
Verifier -> Backend -> Smart Contract (in future phases)
```
The Verifier operates independently of the robot. It does not trust the robot's `COMPLETED` state; it inspects the raw evidence.

## Verifier Identity
**Verifier ID:** `VERIFIER-001`

The verifier is a distinct entity from `NR-001`.

## Verification Rules
1. **Task ID**: Matches expected.
2. **Robot ID**: Matches assigned robot (`NR-001`).
3. **Package ID**: Matches expected package.
4. **Source**: Matches expected source zone.
5. **Destination**: Matches expected destination zone.
6. **RFID**: Matches expected RFID (`D9:33:6A:F8` for `T001`).
7. **Distance**: Must be >= 12.0 meters.
8. **Timestamp**: Must be a valid positive Unix timestamp.
9. **Required Evidence**: All fields must be present.
10. **Proof Hash Integrity**: The `keccak256` hash of the evidence must match the submitted hash.

## Proof Hash Integrity & Tamper Detection
The verifier re-calculates the canonical `keccak256` hash of the supplied evidence. If the evidence was modified (e.g. distance changed from 2.0 to 12.4 *after* hash generation, or vice versa), the calculated hash will not match the submitted hash, and the proof will be rejected. 

## Backend API
- `GET /api/health` - Check backend status
- `GET /api/tasks/:taskId` - Fetch task info from blockchain
- `GET /api/tasks/:taskId/evidence` - Fetch stored proof evidence
- `POST /api/tasks/:taskId/verify` - Submit verification result

## How to Run

```bash
# Run verification for default task (T001)
npm run verify

# Run verification for a specific task
npm run verify -- T002

# Run tests
npm test
```

## Limitations (Phase 7)
- Payment is NOT released yet.
- No blockchain transactions are sent.
- Sensor evidence is simulated.
- Evidence storage is currently in-memory on the backend.
